# Children for Life — childrenforlife.com

Website for **Children for Life**, a nonprofit that protects, educates, and empowers vulnerable children in Benin, Cameroon, DR Congo, Ethiopia, Nigeria, and Tanzania.

## Stack

- **Frontend**: React 19 + Vite + Tailwind CSS + React Router v7 (SPA, code-split routes)
- **Payments**: Stripe Checkout (one-time & monthly subscriptions) via Vercel serverless functions
- **Email**: Resend (contact form, donation receipts)
- **Monitoring**: Sentry (error tracking), Plausible (analytics)
- **Quality**: Vitest + Testing Library + vitest-axe, oxlint, Prettier

## Getting started

```bash
npm install
npm run dev        # start Vite dev server (http://localhost:5173)
npm test           # run tests
npm run lint       # oxlint
npm run build      # production build into dist/
```

The `api/` functions run as Vercel serverless functions. In local dev, Vercel Functions
are not served by the Vite dev server; use `vercel dev` if you need to exercise them
locally.

## Environment variables

Copy `.env.example` to `.env` and fill in values:

| Variable | Used by | Required |
|---|---|---|
| `STRIPE_SECRET_KEY` | `api/create-checkout-session.js`, `api/send-receipt.js`, `api/create-portal-session.js` | Yes (live donations) |
| `RESEND_API_KEY` | `api/contact.js`, `api/send-receipt.js`, `api/subscribe.js` | Yes (contact + receipts + newsletter) |
| `RESEND_AUDIENCE_ID` | `api/subscribe.js` | Yes (newsletter list) |
| `VITE_SENTRY_DSN` | `src/main.jsx` | No (error monitoring) |
| `VITE_CONTENTFUL_SPACE_ID` | `src/lib/content.js` | No (news/stories fall back to local data) |
| `VITE_CONTENTFUL_DELIVERY_TOKEN` | `src/lib/content.js` | No (read-only Delivery token, safe in the browser) |

Never commit real keys — only `STRIPE_SECRET_KEY` and `RESEND_API_KEY` are needed in
Vercel's dashboard (Vercel reads server-side env vars; `VITE_`-prefixed vars are inlined
at build time).

## API endpoints

| Endpoint | Purpose |
|---|---|
| `POST /api/create-checkout-session` | Create a Stripe Checkout session (one-time or monthly) |
| `POST /api/send-receipt` | Verify a paid Stripe session and email a donation receipt via Resend |
| `POST /api/create-portal-session` | Open the Stripe Customer Portal for a donor (manage/cancel monthly gifts) |
| `POST /api/matching-gift` | Send an employer matching-gift request via Resend |
| `POST /api/volunteer-apply` | Send a volunteer application via Resend |
| `POST /api/career-apply` | Send a job application via Resend |
| `POST /api/gift-aid` | Send a tax-receipt / Gift Aid declaration via Resend |
| `POST /api/subscribe` | Add an email to the Resend newsletter audience + send a welcome email |
| `POST /api/contact` | Send contact-form messages via Resend |

## Deployment

- **Primary**: Vercel — auto-deploys on push to `master` (see `vercel.json`).
- **Alternative**: GitHub Pages — `npm run deploy` builds with `GITHUB_PAGES=true`
  (the router picks a `/ChildernforLife.com` basename) and publishes `dist/`.

Go-live checklist lives in [`NEXT-STEPS.md`](NEXT-STEPS.md).

## Project structure

```

public/              Static assets (favicon, manifest, robots.txt, sitemap.xml, og-image.png)

  components/        Navbar, Footer, PageSEO (SEO + JSON-LD), ErrorBoundary

  hooks/             Shared hooks (e.g. useScrollReveal)

```

## Notes

- **CMS**: news & impact stories can be published from Contentful (`src/lib/content.js` +
  `src/hooks/useContentItems.js`). When `VITE_CONTENTFUL_*` are unset, pages render the
  local data files — see `NEXT-STEPS.md` §8 for the content-model setup guide.

- **Adding news or impact stories**: edit `src/data/news.js` / `src/data/impactStories.js`
  — each entry needs a unique `slug` (becomes the URL), `title`, `tag`, `date` (news only),
  `img`, `excerpt`, and `body` (array of paragraphs). Article pages render automatically
  at `/news/:slug` and `/stories/:slug`. Then regenerate the sitemap with
  `node scripts/generate-sitemap.mjs`.
  Current article bodies are placeholder copy written from the article titles — replace
  them with the organization's real content.
- **Campaigns**: edit `src/data/campaigns.js` — each entry has `slug`, `name`, `tagline`,
  `goal`/`raised` (USD, updated by the org; Stripe can sum by `campaign` metadata once
  live), `img`, and `body`. Donations via `/donate?campaign=<slug>` are tagged with the
  campaign in Stripe metadata (server-side allowlisted — keep the slug list in
  `api/create-checkout-session.js` in sync).
- **Sitemap**: `public/sitemap.xml` is generated by `scripts/generate-sitemap.mjs`
  (static routes + slugs pulled from the data files). Regenerate with
  `node scripts/generate-sitemap.mjs` after adding pages or content.
- **Impact stats**: edit `src/data/impactStats.js` (homepage "Our Global Impact" band).
- Images: `public/og-image.png` is generated by `scripts/generate-og-image.py`
  (requires Python + Pillow); regenerate with `python scripts/generate-og-image.py`.
  Card-grid WebP variants (`src/assets/*.card.webp`, 640px) and full-size
  (`src/assets/*.full.webp`, 1024px) are generated by `scripts/optimize-images.py`;
  the homepage serves these instead of the JPGs. Photographic assets are **JPEG** (`.jpg`) — keep the
  extension matching the actual encoding; do not enable the `webp` option in
  `vite-plugin-imagemin` (it writes WebP bytes into the original asset names).
- `stats.html` at the repo root is a Vite bundle-analysis report (generated with
  `vite build -- --open`); it is not part of the site.
